# Task 0004: Type-safe scene loading through a loader scene

## Goal

Add a typed scene-loading API so gameplay code never passes raw scene-name strings:

- `SceneName` enum generated from the scenes in `Assets/AngryBirds/Scenes`.
- `Infrastructure.SceneManager.Load(SceneName)` starts a transition.
- `Infrastructure.SceneManager.LoadAsync(SceneName)` starts a transition and returns the
  `AsyncOperation` of the target scene.
- Both transitions show a dedicated `Loader` scene with a progress bar instead of a frozen
  frame while the target scene streams in.

Feature document: `Doc/Features/core-gameplay.md`.

## Affected areas

- `Assets/AngryBirds/Scripts/Infrastracture/SceneManager.cs`
- `Assets/AngryBirds/Scripts/Infrastracture/SceneName.cs` (generated)
- `Assets/AngryBirds/Scripts/Core/Loading/ILoadingScreen.cs`
- `Assets/AngryBirds/Scripts/Ui/LoadingScreenView.cs`
- `Assets/AngryBirds/Scripts/Editor/Builder/SceneNameGenerator.cs`
- `Assets/AngryBirds/Scripts/Editor/Builder/GameContentBuilder.cs`
- `Assets/AngryBirds/Scripts/Infrastracture/Bootstrap/LevelBootstrap.cs` (alias for Unity
  `SceneManager`, because the project now has its own `Infrastructure.SceneManager`)
- `Assets/AngryBirds/Scenes/Loader.unity` (generated by the content builder)

## Plan

1. Generate `SceneName` from the scene assets and keep the generator available as
   `Tools/AngryBirds/3. Generate Scene Names`.
2. Implement `SceneManager` as a lazily created persistent service. It loads the loader
   scene additively, starts `LoadSceneAsync` for the target with deferred activation,
   forwards `0..1` progress to the loader view, then activates the target (which unloads
   the loader scene because the target uses `LoadSceneMode.Single`).
3. Keep the UI decoupled through `ILoadingScreen`; `LoadingScreenView` implements it and
   updates an `Image` fill and a percentage label.
4. Extend `GameContentBuilder` to create `Loader.unity`, wire the progress widgets, add the
   loader and boot scenes to the build settings, and regenerate `SceneName`. The loader
   scene can be built alone with `Tools/AngryBirds/4. Build Loader Scene`, or together with
   the levels via `Tools/AngryBirds/2. Build Game Content`.

## Acceptance criteria

- [ ] `SceneManager.Load(SceneName.Level_02)` and
      `SceneManager.LoadAsync(SceneName.Level_02)` are valid and type-safe.
- [ ] Transitioning displays the loader scene with a progress bar until the target scene
      activates.
- [ ] Calling a load while another one is active is ignored with a warning.
- [ ] A missing target or loader scene produces a clear Console error/warning instead of a
      silent failure.
- [ ] Re-running `Tools/AngryBirds/2. Build Game Content` creates `Loader.unity`, registers
      it, and keeps `SceneName.cs` in sync.

## Validation performed

- `dotnet build Assembly-CSharp.csproj` and `dotnet build Assembly-CSharp-Editor.csproj`
  compile with 0 errors (new files were added to the generated project files for the check).
- Unity play-mode validation is pending: run `Tools/AngryBirds/4. Build Loader Scene` (or
  the full `Tools/AngryBirds/2. Build Game Content`) once after the scripts recompile, then
  play a level and call the new API.

## Outcome

- API implemented; `Loader.unity` and the generated enum are produced by the content
  builder. Existing `LevelBootstrap` navigation was intentionally left unchanged so future
  dynamic level names keep working; switching it to `SceneName` is a separate change.
- `SceneManager` uses the project namespace `AngryBirds.Infrastructure` (the file sits in
  the existing `Scripts/Infrastracture` folder). Because the project type now shadows
  Unity's `SceneManager` inside this namespace, `LevelBootstrap` uses the
  `UnitySceneManager` alias for the Unity API.
