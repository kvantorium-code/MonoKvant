# Core gameplay

The game is a 2D Angry-Birds-like slingshot puzzle. The player launches a limited set of
birds to knock down structures and defeat green pigs. All content is generated by editor
tools and all visuals are procedural placeholder art that can be replaced file by file.

## Levels

- Three generated levels (`Level_01` … `Level_03`), each a data-driven `LevelDefinition`
  asset: pig/block layout, bird count, star score thresholds, slingshot position, ground
  size and camera bounds.
- The levels are data, they are all played in the single `Gameplay` scene: the `LevelCatalog`
  asset lists them in play order and `LevelSpawner` spawns the chosen level into the scene,
  so the scene itself is level agnostic.
- Structures are made of wood, glass and stone blocks placed by the level definition.
- A level is won when all pigs are destroyed, and lost when the birds run out first.

## Slingshot and controls (new Input System only)

- Mouse/touch: drag the loaded bird from the slingshot; the trajectory preview shows a
  dotted arc. Releasing launches the bird. A grab only starts when the pointer is close
  enough to the bird, so pressing UI buttons never fires the slingshot.
- Gamepad: aim with the left stick (dead zone guarded), release with the fire action.
- The active input handler is the new Input System (`activeInputHandler: 1`); `GameInput`
  exposes pointer/stick state to gameplay and the UI is driven by `InputSystemUIInputModule`.
- `R` (or the HUD restart button) restarts the current level.

## Actors and destruction

- Birds, pigs and blocks have health and a score value; they take damage on hits and
  flash when hit. When depleted they spawn flying debris and a burst effect.
- Blocks pick the artwork variant (square/wide/tall) closest to their spawned aspect
  ratio and render exactly at their spawned size.

## Score and stars

- The score counts destroyed pigs and blocks. At level end 1–3 stars are awarded from the
  `twoStarScore` / `threeStarScore` thresholds.
- The HUD shows the current score, birds left and the live star row while playing.

## Camera

- The camera is orthographic and follows the action with `CameraRig`, clamped to the
  bounds defined by the current level.

## UI

- HUD: level name, score, birds left and the live star row on the left; restart button in
  the top-right corner.
- Result overlay: shown on level end with the title, stars, score and NEXT LEVEL / RESTART
  buttons. The overlay renders above the HUD.

## Scene loading

- The game has three scenes: `Boot` (build index 0, holds the project scope), `Gameplay`
  (plays every level) and `Loader` (the transition curtain).
- The flow switches scenes through `IGameSceneManager` / `GameSceneManager`, the only place
  that calls `UnityEngine.SceneManagement.SceneManager`. `GameplayState` takes the level
  from the `LevelCatalog` and loads the `Gameplay` scene with it.
- A transition is fully additive so the curtain survives it: `Loader` is loaded additively,
  the target scene streams in with deferred activation while `GameSceneManager` forwards the
  progress to `ILoadingScreen` (`LoadingScreenView`), then the target activates, the previous
  content scene and the curtain are unloaded. `Boot` is never unloaded.
- Scene names come from the generated `SceneName` enum
  (`Scripts/Infrastracture/Flow/SceneName.cs`); regenerate it with
  `Tools/AngryBirds/3. Generate Scene Names` after adding a scene.

## Content pipeline

- `Tools/AngryBirds/1. Generate Placeholder Art` — writes the procedural sprite set
  (mipmapped, bilinear, uncompressed).
- `Tools/AngryBirds/2. Build Game Content` — (re)builds prefabs, level definitions, the level
  catalog, the `Boot`, `Gameplay` and `Loader` scenes and registers them in the build settings
  (`Boot` is the first scene, the game starts from it). Running it again is meant
  to reproduce the same result, including keeping asset references valid.
