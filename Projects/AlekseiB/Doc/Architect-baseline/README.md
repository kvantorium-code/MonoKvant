# Architect Baseline

Purpose:
- Architectural baseline of the project: layers, main constraints, dependency rules, module boundaries.
- Single source of truth for structural decisions that future code must respect.
- Detailed decisions are recorded as ADR files in `Doc/ADR`.
- The workspace baseline is `Docs/AI_AGENT_ARCHITECTURE_BASELINE.md` (repo root); this file mirrors it for the project.

Current baseline:
- Unity `6000.5.3f1`, Universal Render Pipeline.
- All game-specific content lives under `Assets/AngryBirds/`.
- New game-specific code and assets must not be placed directly in the `Assets` root.

Layers:
- `Scripts/Infrastracture` - bootstrap, composition root, DI scopes, scene transitions, platform services. Wiring only, no gameplay logic.
- `Scripts/Ui` - UI views and controllers, widgets. No direct service creation.
- `Scripts/Localization` - localization keys, adapters, language switching, text binding. No business logic.
- `Scripts/Core` - gameplay/domain logic, free of UI dependencies where possible.
- `Scripts/Editor` - editor-only tooling (`Editor` folder), including the content builders under `Editor/Builder`.

Rules:
- Dependencies point inwards: `Ui` -> `Core`, `Infrastracture` -> `Core`. `Core` never depends on `Ui` or `Infrastracture`.
- `Infrastracture` contains wiring, composition root and integrations, never gameplay logic.
- `Ui` must not create services; pass dependencies through DI or explicit initialization.
- `Localization` holds adapters and keys only, no business logic.
- Assembly definition files (`.asmdef`) are created only after explicit agreement or when a task explicitly requires them.
- Avoid heavy logic in `Update()`, cache component references, prefer event-driven logic.

Scene flow (ADR-0002):
- `Boot` (build index 0) hosts the project scope and lives for the whole application.
- Scene transitions go through `IGameSceneManager` only: the `Loader` curtain scene is loaded additively, the target scene loads additively with deferred activation, then the previous content scene and the curtain are unloaded. Direct `SceneManager.LoadScene` calls elsewhere are forbidden.
- Scene names come from the generated `SceneName` enum (`Scripts/Infrastracture/Flow/SceneName.cs`, regenerated by `Tools/AngryBirds/3. Generate Scene Names` / the content build), never raw strings.

UI pattern: View + Controller (ADR-0002):
- A view (`XxxView : MonoBehaviour`) is pure display: setter methods, `Show`/`Hide`, `event Action` press notifications. No services, no domain objects.
- A controller (plain C# class registered in the scene scope) subscribes to view events and domain events, pushes data into the view, and decides what happens next. Subscriptions are removed in `Dispose`.
- Example: `HudView` + `HudController`; `GameplayEntryPoint` only wires parts together.
